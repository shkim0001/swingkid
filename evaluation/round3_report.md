## 5. 세 회차에서 배운 것

1. **오프라인 20/20 은 품질을 보장하지 않습니다.** 가짜 모델로는 v1 의 품질 문제 4건이 하나도 보이지 않았습니다. 라이브 + LLM 심사가 있어야 잡힙니다.
2. **실패 원인은 여러 곳에 있습니다.** 세 회차의 문제는 검색기 · 에이전트 입력 · 생성기 · judge · 평가셋 전제 · 환경으로 나뉘었습니다. 원인을 가르지 않고 프롬프트만 고쳤다면 2번(judge)·20번(평가셋)은 고칠 수 없었습니다.
3. **채점기도 바뀐 시스템에 맞춰야 합니다.** `TOP_K` 를 올리자 judge 의 근거 제한이 새 오판을 만들었습니다. 평가 코드도 회귀 테스트를 둡니다(`tests/test_llm_judge.py`).
4. **바깥 환경에 기대는 문항은 기대값을 분리합니다.** 웹 결과는 실행마다 다르므로, 결과 자체가 아니라 "지어내지 않았는가"를 확인하도록 라이브 기대값을 정했습니다.
